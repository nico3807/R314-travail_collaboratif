TP - BUT MMI 2 · R3.14 Déploiement de service

Travail collaboratif sur un projet de développement, versionnement

Un TP de 3 heures, en binôme, pour s'approprier Git, GitHub et VSCode au travers d'incidents provoqués volontairement : synchronisation, conflit, branches, Pull Request et relecture de code.

Dépôt de travail

Tout se passe dans un unique dépôt GitHub partagé par le binôme, nommé exactement :

depot-partage

Organisation

Binômes fixes. Les rôles « Théodora » et « PLK » s'alternent d'un scénario à l'autre : chacun·e doit avoir poussé, tiré, résolu un conflit et fait une revue de code au moins une fois.

Outils

Git en ligne de commande, VSCode (panneau Source Control, éditeur de fusion, extension GitHub Pull Requests and Issues) et un compte GitHub par étudiant·e.

Déroulé de la séance

  • Accueil, objectifs, présentation du dépôt depot-partage et des binômes. Vérification rapide des prérequis (voir la page « Prérequis », à faire avant la séance).
  • Scénario 0 - Prise en main solo dans un dépôt bac à sable.
  • Scénario 1 - Création du dépôt commun, ajout du binôme, premier commit synchronisé.
  • Scénario 2 - Modifications parallèles sans conflit.
  • Scénario 3 - Le conflit provoqué et sa résolution.
  • Scénario 4 - Branche dédiée, Pull Request et revue de code croisée.
  • Scénario 5 - Filet de sécurité : git revert et .gitignore.
  • Préparation SAÉ - Déclarer son compte GitHub, rejoindre le dépôt privé Test_arcade, se placer sur la branche de son groupe et faire relire son travail par son équipe (voir la page « Préparation SAÉ »).

Objectifs pédagogiques

Savoir-faire technique

  • Cloner, ajouter, committer, pousser, tirer.
  • Créer et fusionner une branche.
  • Résoudre un conflit avec l'éditeur de fusion de VSCode.
  • Ouvrir, commenter et fusionner une Pull Request.
  • Annuler un commit partagé sans réécrire l'historique.

Posture collaborative

  • Communiquer avant de pousser un travail qui touche au même fichier.
  • Écrire des messages de commit compréhensibles par l'autre.
  • Accepter une remarque de revue de code sans la prendre pour une critique personnelle.
  • Savoir qui a fait quoi et pourquoi, à tout moment, grâce à l'historique.

Avant de commencer

Chaque étudiant·e doit avoir terminé la page Prérequis avant la séance : Git installé, compte GitHub créé, VSCode connecté. Le temps de la séance est entièrement consacré aux scénarios collaboratifs.
